# MatterForge Lab 0.8.0

A local scientific playground for exploring how simple interaction rules can produce connected structures. This is an educational model, not a chemistry prediction tool. No account, cloud service, API key or dedicated GPU is required. The simulation works offline. Optional update checks contact GitHub, the optional AI explainer contacts a user-selected loopback server, and reference links open the system browser only when requested.

## Install the Windows app

Download [the latest Windows installer](https://github.com/wardgeys1993-web/MatterForgeLab/releases/latest), run it and open MatterForge Lab from the Start menu or desktop shortcut. Windows 10 or newer, 64-bit, is required. Node.js and a development server are not needed to use the installed app.

Use **App updates** in the header to check GitHub, download a verified release, and restart when ready. Updates are checked manually. Signed release metadata and installer checksums are verified before installation. Builds currently have no Microsoft Authenticode certificate, so Windows may show an unfamiliar-publisher warning.

Settings, experiment A and research checkpoints stay in your local app-data folder across updates. The desktop chamber is saved every ten seconds and on normal close. Pause research before restarting to save the current partial trial. To move browser experiments into the desktop app, export JSON in the browser and import it in the app. Browser and desktop storage are separate.

The **Research lab** searches bounded parameter combinations, compares finalists with a baseline, and uses fresh confirmation seeds before reporting its result. Sessions support pause, resume, checkpoint recovery, JSON import/export and trial replay. The optional local AI explainer can explain recorded evidence, but cannot change measurements or run code. See [research architecture](docs/RESEARCH_AUTONOMY.md).

## Develop on Windows

Install a current Node.js LTS release, open PowerShell in this folder, then run:

```powershell
npm install
npm run dev
```

Open the local address printed in the terminal. Leave that terminal running while using the app. Once dependencies have been installed, the application can run offline. To create a production build, run `npm run build`. Run the simulation tests with `npm test`. Browser tests use a local QA server on port 5174 and an isolated Chrome context. Check that the port is free before starting the QA server. Desktop packaging and publishing instructions are in [RELEASING.md](docs/RELEASING.md).

## Try the first experiment

Choose **Start my first experiment**. The colored beads move and form reversible connections. Choose a connected group of four, a roughly square loop of four, or a roughly triangular loop of three as the target; the same particles must meet the chosen condition for two simulation time units. Select **Try the triangle example** in the shape controls to watch a seeded triangle form. The example starts a fresh run and changes several settings, while leaving saved experiment A intact. A triangle needs at least one same-type compatibility rule, A + A or B + B, because A + B bonds alone cannot close an odd-numbered loop. Choose **Make a square** in the guide and start its seeded example to watch the corner-site model assemble. Circles represent type 1 sites, diamonds represent type 2 sites, and gold outlines indicate occupied sites. Choosing a different site layout starts a fresh paused run; save the current experiment as A first if you want to keep it. With **Custom site angle**, adjust the angle between the two sites. This changes the alignment forces on existing bonds and restarts target timing and history.

The compatibility buttons choose which particle-type pairs count as intended bonds. In a directional layout, **Site type rules** assign a type to each of the two sites and choose allowed site-type pairs. Every particle shares that same two-site template. Both particle and site rules must allow a bond for it to count as intended; lower selectivity can still permit unintended pairings. Changing site types or pair rules reclassifies existing bonds and restarts target timing and history. Site-type rules have no effect in any-direction mode. Changing a rule reclassifies existing bonds and restarts the target timer and history. In **Build in layers**, a separate interactive process model lets parts form modules and modules join a group. Its mismatches and repairs are stochastic rules, not molecular physics. It resets when you leave that guide and is not included in experiment A. The parallel calculator is idealized arithmetic, not a manufacturing forecast.

Click a question mark for a plain-English explanation. Save a run as A, change a setting, and compare it with the current run. Restore A to resume from its exact saved state. The seed is reproducible for the same settings and sequence of steps. Count or seed changes start a fresh run. Drag the chamber to pan, use the zoom buttons, or focus the chamber and use the arrow keys. Force overlays show an attraction range, a repulsion boundary and net force arrows.

The **controlled study** compares two values of one selected setting, with 100 paired motion seeds by default. For directional particles it can also compare either site type or the allowed site-pair rules. By default the browser draws distinct seeds uniformly without replacement from the nonzero 32-bit seed space; consecutive seeds remain available for reproducible examples. Repeat the current random seed list with **Repeat these seeds** while the results remain in the lab. The JSON export records the exact seeds, settings, results and uncertainty calculation. Use **Import study JSON** to review and rerun a complete exported study without changing the chamber or saved experiment A. The lab compares the replayed seed, arrangement seed, first success, final stability and unintended bonds with the saved records. A match does not verify the full trajectory or the file’s origin. Older model versions may produce different results; the app warns when the model marker differs. Random-sampling provenance in an editable imported file cannot be independently verified. The remaining model settings, target and duration are held fixed. By default every run starts from the same arrangement; alternatively each seed pair gets a new arrangement. The A and B runs in each pair share particle positions and orientations, except that changing particle count adds or removes particles, and changing concentration scales positions with the chamber so relative positions match. Initial random states are paired but random draws can diverge as behavior changes. Results count runs that held the target for two simulated time units at least once before the deadline, alongside those still stable at the end and a paired breakdown. JSON captures settings and per-run results and can be imported for replay; CSV contains per-run results and cannot be imported as a study. Export them before leaving the lab. For randomly sampled seeds, the study shows approximate 95% [Wilson score intervals](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm) for each success rate and a conservative 95% [Hoeffding bound](https://www.cs.rpi.edu/academics/courses/spring06/random/hoefding.pdf) for the paired difference. These ranges describe sampling over this finite seed space and the chosen starting-arrangement procedure. They assume the settings were selected before sampling; repeated tuning on the same seeds is exploratory. A fixed arrangement does not measure performance across arrangements. Wilson ranges are approximate, and overlapping individual ranges are not a test of the paired difference. Consecutive seeds do not receive these sampling ranges. The reported percentages describe this teaching model and chosen starting conditions, not physical success rates or proof of real-world causation.

The **multiple-seed study** runs fresh simulations locally in a background worker, using the chosen seed range and simulated duration. It can compare the saved A settings with the current settings without replacing the chamber. It reports how many seeds reached the target before the deadline, how many remained stable at the end, and the median first-success time among successful seeds. Each seed is visible individually. JSON exports include the recorded settings and outcomes; CSV exports contain the per-run outcomes. Results stay tied to the captured settings even if the controls change. Shared seeds do not guarantee identical random events across different settings. These are small samples of a teaching model, not evidence of real-world manufacturing success.

The browser stores settings and one saved experiment locally. JSON export and import preserve the full particle state, including orientations, occupied sites and the random generator. The current format is version 5. Imports are limited to 2 MB and validated before replacing the current state. Versions 1 through 4 are upgraded in memory with unrestricted site pairings and their original bonding probabilities preserved. CSV export contains rolling metric samples; chamber PNG exports the rendered canvas. Back up important experiments as JSON because clearing browser data removes local saves. Compare runs at the same simulation time and seed when investigating a single setting. One run alone cannot prove causation.

## What the model actually does

The independent engine advances a two-dimensional bead system in fixed steps of 0.025 arbitrary time units. Seeded Gaussian displacements approximate thermal agitation in an overdamped, Brownian-inspired update. Short-distance repulsion discourages overlap; a finite-range attraction draws nearby beads together. The selected compatibility rules determine which types may form intended stochastic spring-like bonds at close distance. Lower selectivity also permits unintended bonds. Each bead has at most two connections. Bonds break stochastically, with a rate influenced by temperature and attraction, or if stretched beyond a cutoff. Positions and forces are bounded for numerical stability.

In directional mode, particles rotate and their two sites must be free and face one another within 0.9 radians before a bond can form. When multiple free aligned sites are available, the model prefers an allowed site-type pairing; otherwise it can form an unintended pair at reduced probability. Existing bonds apply approximate angular alignment and tangential forces. The custom layout permits angles from 30° to 180°. The user-selected bond formation chance applies per eligible step, from 0% to 40% for compatible pairs; unintended pairs have their chance reduced by selectivity. Switching site layouts preserves the chosen chance, while the seeded square example explicitly sets it to 20%. These are illustrative probabilities, not measured chemical rates. For a square, the model requires a four-bond loop, sides between 0.75 and 1.8 arbitrary units with a maximum side ratio of 1.4, and diagonals between 1.15 and 1.7 times the mean side with a maximum diagonal ratio of 1.4. The same four particles must retain the qualifying shape for two simulated time units. For a triangle, the model requires a three-bond loop, each side between 0.75 and 1.8 arbitrary units, with the longest side no more than 1.4 times the shortest. The same three particles must retain the qualifying shape for two simulated time units. Both shape indicators are binary, not estimates of partial completion.

This deliberately simplified model is not quantitatively calibrated. It has no atomistic structure, explicit solvent, hydrodynamics, chemical reactions, physical units, force-field calibration or validated equilibrium distribution. Attraction, directional sites, bond formation and breakup use illustrative rules, not a derived molecular potential or verified thermodynamic kinetics. Do not infer real reaction rates, free energies, manufacturing feasibility or chemical structures from it. Higher agitation increases both movement and the modeled break rate; results depend on other settings as well. [NIST research on directional interactions](https://www.nist.gov/publications/coupling-isotropic-and-directional-interactions-and-its-effect-phase-separation-and) provides scientific context, not validation of this model.

## Architecture

- `src/simulation/engine.ts`: seeded simulation, state, metrics and import/export validation. No UI dependency.
- `src/simulation/hierarchy.ts` and `src/HierarchyDemo.tsx`: separate discrete process model and interface.
- `src/simulation/batch.ts`, `src/simulation/batch.worker.ts` and `src/BatchLab.tsx`: bounded multi-seed studies in a local worker.
- `src/Chamber.tsx`: Canvas renderer and camera interaction.
- `src/ExperimentGuide.tsx`, `src/Glossary.tsx` and `src/ManufacturingLadder.tsx`: guided exploration and teaching views.
- `src/LessonIllustration.tsx`: conceptual topic-specific and interactive learning diagrams.
- `src/App.tsx`: React navigation, playback, explanations, controls and local persistence.
- `src/content.ts`: educational content and references.
- `src/simulation/engine.test.ts` and `src/simulation/hierarchy.test.ts`: numerical rules, reproducibility and state tests.

React and Vite provide a small local UI and build; Canvas renders the 2D teaching model without a 3D GPU dependency. Vitest exercises the standalone engine and Playwright covers selected browser flows. The [proposed backend contract](docs/SIMULATION_BACKENDS.md) separates simulated and physical units and records model and software versions. A real molecular dynamics backend would need validated force fields, suitable integrators, parameterization, units, convergence studies and experimental comparison. [OpenMM](https://openmm.org/) and its [user and theory guide](https://docs.openmm.org/latest/userguide/) are useful starting points for suitable molecular dynamics, not a drop-in validation of this model. [DNA origami research](https://www.nature.com/articles/nature04586) is an example of programmable molecular assembly, not evidence of a universal fabricator. See [performance notes](docs/PERFORMANCE.md) for a bounded engine-only measurement.

## Learn by experimenting

Explore why nearby particles can attract but resist overlap, why randomness changes encounters, how compatibility affects errors, and why keeping an assembly together differs from briefly forming it. The target is an analogy for designing local rules, not a blueprint for matter synthesis.
